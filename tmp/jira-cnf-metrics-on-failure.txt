h2. Summary

eco-gotests RAN PTP failures should include point-in-time metric diagnostics in CI artifacts, comparable to cnf-gotests {{printPTPInfo()}} behavior. Today we collect k8sreporter dumps ({{openshift-ptp}}, {{cloud-events}}) and PTP operator must-gather, but must-gather does not include Prometheus instant queries or raw {{localhost:9091/metrics}} from linuxptp pods.

h2. Background

* cnf-gotests {{AfterEach}} on failure: PTP daemon metrics via {{curl -s localhost:9091/metrics}} per linuxptp pod; consumer logs from {{cloud-events}}.
* eco-gotests {{JustAfterEach}}: {{reporter.ReportIfFailed}} + {{mustgather.MustGatherIfFailed}} ({{tests/cnf/ran/ptp/ptp_suite_test.go}}).
* PTP must-gather tarball: inspect YAML, pod logs, {{ptp-captures/}}, K8s events ({{event-filter.html}}) — no dedicated {{openshift_ptp_*}} metric snapshot.
* Tests assert metrics via Prometheus during execution ({{tests/cnf/ran/ptp/internal/metrics}}); that state is not persisted on failure.

h2. Scope

# Failure-only, best-effort hook (skip skipped tests; do not mask original failure).
# Per linuxptp daemon pod: capture {{localhost:9091/metrics}} into failed-test report dir (e.g. {{ptp-metrics/<pod>_9091_metrics.txt}}).
# Prometheus instant-query dump for queries already used in PTP tests (clock state, clock class, process status, etc.) into e.g. {{prometheus-metrics/instant-queries.json}}.
# Integrate alongside existing failure reporting in PTP suite {{JustAfterEach}} (new small package acceptable, e.g. {{internal/failurediagnostics}}).
# Time-bounded collection (suggest total budget <= 3 minutes); log partial failures without failing the job.

h2. Out of scope (follow-ups)

* Upstream PTP must-gather image changes.
* Consumer sidecar HTTPS metrics in {{cloud-events}} (reporter already collects consumer pod logs).
* Non-PTP suites unless explicitly expanded later.

h2. Acceptance criteria

* Failed PTP test report folder contains {{ptp-metrics/}} with at least one non-empty artifact per linuxptp daemon on the spoke under test.
* When Prometheus is reachable on failure, report contains documented instant-query dump for core {{openshift_ptp_*}} series used by existing tests.
* Passing/skipped tests do not run this collection (no meaningful green-job regression).
* Unreachable cluster/Prometheus: original failure unchanged; collection errors logged and optionally {{metrics-collection-errors.txt}}.
* Brief doc/README for artifact paths for QE triage.
